# lem_venue_sales — Продажі закладів

Odoo-модуль для збору даних продажів (Z-звітів / закритих касових змін) з POS-систем закладів мережі. Провайдер-агностичний: кожна POS-система підключається через власний конектор, а дані нормалізуються у спільну модель незалежно від джерела.

## Як це працює

```
venue.sales.connection  →  venue.sales.location  →  venue.sales.session
   (підключення до          (заклад, = ресторан/       (1 запис = 1 закрита
    провайдера: URL,          департамент у POS)         касова зміна, Z-звіт)
    логін/пароль)
                                    │
                                    └── venue.sales.register (каса)
```

- **`venue.sales.connection`** — облікові дані підключення до одного провайдера (URL сервера, логін/пароль або токен). `password`/`login` доступні лише групі `base.group_system`.
- **`venue.sales.location`** — заклад мережі (в термінах провайдера — ресторан/департамент/точка продажу). Список закладів отримується автоматично при перевірці з'єднання.
- **`venue.sales.register`** — каса в межах закладу, визначається органічно з даних, що синкаються (по номеру каси). Має чекбокс "Фіскальна каса" — нефіскальні (службові/адмінські) каси приховані зі звітів за замовчуванням.
- **`venue.sales.session`** — власне касова зміна: суми готівкою/карткою, кількість чеків, статус прийняття бухгалтерією тощо. Upsert-ключ — `(location_id, external_id)`, тому повторний sync за той самий період безпечний (ідемпотентний).

Синхронізація — або вручну через візард ("Завантажити дані" на картці закладу), або автоматично щоденним cron (`_cron_auto_sync_restaurants`) з ретраями при невдачі.

## Підтримувані провайдери

### Syrve (`connectors/syrve.py`)

Legacy RMS API (`{server_url}/resto/api/...`), не Cloud API 2.0. Авторизація — сесійний токен через `GET /auth`, переданий як `?key=` на кожному наступному виклику, закривається `GET /logout`.

Використовувані endpoints:

| Метод | Шлях | Призначення |
|---|---|---|
| GET | `/auth` | Логін, отримати сесійний токен |
| GET | `/logout` | Закрити сесію |
| GET | `/corporation/departments` | Список закладів мережі (визначення ID закладу) |
| GET | `/v2/cashshifts/list` | Список касових змін за період для закладу |
| GET | `/reports/olap` | Кількість чеків по зміні (єдине джерело цього поля — `v2/cashshifts/list` його не містить) |

### Poster (`connectors/poster.py`)

Авторизація — статичний токен (`account_id:hash`) як `?token=`, без сесії логін/логаут. Poster повертає HTTP 200 навіть при помилках авторизації (з `{"error": {...}}` у тілі), тому кожен виклик перевіряє це поле сам, не покладаючись на HTTP-статус.

## Права доступу

- `base.group_system` — повний доступ, включно з обліковими даними підключень.
- `group_venue_sales_user` — перегляд закладів/змін і ручний запуск синку, без доступу до `venue.sales.connection` (де зберігаються логін/пароль провайдера).
